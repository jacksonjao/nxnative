# Example: Super Mario Galaxy on Apple TV

This is the first game-specific recipe for the Apple TV build path in [nxnative-tvOS](../README.md). Galaxy is an example, not the scope of the fork. The work adds a pre-game settings screen and a classic-Metal presentation fallback for Vulkan games on Apple TV hardware without Metal 4. The build targets an A12-compatible CPU baseline and runs on that chip and newer Apple TV chips; the repository is not limited to A12.

## Compatibility status

- The app targets tvOS 26 or later. The upstream TVPort project documents its tested Apple TV as a 3rd-generation 4K model with A15 and tvOS 27.2.
- The classic presenter is experimental. Galaxy boots and reaches Vulkan frame presentation on the 2nd-generation Apple TV 4K, but the image has not yet been confirmed through a complete visual play test. Do not advertise this branch as a verified playable release until that check passes.
- Metal 4 pipeline controls are shown only when the game exposes them and the current GPU supports Metal 4. A MetalFX option additionally requires `MTLFXSpatialScalerDescriptor` to report that its Metal 4 spatial scaler is available. Unsupported controls are hidden; graphics capability selection is made at runtime.
- Options that do not apply to tvOS or the current game graphics API are omitted. Galaxy uses Vulkan, so NVN-only pipeline archive, pipeline prebuild, frame-buffering and encode-thread options do not apply. Touch haptics also do not apply to Apple TV.

## Requirements

- An Apple silicon Mac running macOS 26.6 or later, with Xcode and the tvOS and iOS SDKs installed. The shader libraries are built for iOS and loaded by the tvOS app.
- Homebrew packages `xcodegen`, `zstd`, and `glslang`, plus the .NET 10 SDK. Run `TVPORT_DATA="$PWD/.local-data" python3 tvport/backend.py doctor` for setup checks that keep helper data in this checkout. The generic [Apple TV build guide](apple-tv-build.md) explains the full workflow.
- An Apple ID added in Xcode, a tvOS device in Developer Mode, and the Apple TV paired in **Xcode > Window > Devices and Simulators**.
- Your own Super Mario Galaxy game dump, update, and `prod.keys`. NSP and XCI are supported; compressed NSZ/XCZ files are also accepted by the build script. Keep the base game and its update together in one game folder.

Game files, keys, generated binaries and extracted data are not part of this repository. The `.gitignore` excludes common local game and build outputs.

## Prepare the Mac

From the repository root:

```sh
TVPORT_DATA="$PWD/.local-data" python3 tvport/backend.py doctor
```

Install any missing items listed by `doctor`. Then create TVPort's Python environment:

```sh
TVPORT_DATA="$PWD/.local-data" python3 tvport/backend.py setup
```

Keep the game folder and keys outside the repository. For example:

```text
~/Games/Super Mario Galaxy/
  Super Mario Galaxy [010099C022B96000][v0].nsp
  Super Mario Galaxy [010099C022B96000][v327680].nsp
~/Keys/prod.keys
```

The update's package version `v327680` is version 1.3.1. A valid XCI base can be used in place of the base NSP.

## Build and install

Find the Apple TV device identifier in **Xcode > Window > Devices and Simulators**, or run `python3 tvport/backend.py devices`. Build and install with:

```sh
TVPORT_DATA="$PWD/.local-data" DM_LANG=es-419 python3 tvport/backend.py build \
  "$HOME/Games/Super Mario Galaxy" \
  --keys "$HOME/Keys/prod.keys" \
  --device APPLE_TV_DEVICE_ID \
  --mode docked \
  --texture-cap 512
```

If the backend cannot find a signing team, pass the Team ID from **Xcode > Settings > Accounts** with `--team TEAM_ID`. The initial extraction and shader preparation can take 30–60 minutes; later builds reuse the generated work folder beside the game files.

The signed app is made in the game's local `_build` directory. Do not commit that directory or share its `.app`: it contains rewritten game code and game-specific shader data.

## Startup menu

The Apple TV app shows its settings before the game starts. Move focus with the Siri Remote or a connected controller, open a setting, select a value, and choose **Start game**. Choices are saved on that Apple TV and appear again at the next launch.

The menu reads available choices from `dm/launcher.json`, the same per-game settings list generated by the build. It supports choices, toggles, and numeric ranges. It omits touch-only settings and checks MetalFX support at runtime, so the same source can present different options on older and newer Apple TV hardware.

## Notes for contributors

- `dm/ios/SourcesTV/TVPlayers.m` builds the settings menu and stores choices in `NSUserDefaults`.
- `dm/ios/project_tv.yml` sets an A12-compatible CPU baseline so the same app binary can run on A12 and newer chips; graphics feature availability is detected separately at runtime.
- `dm/gfx/nvn/nvn_mtl.m` keeps the existing Metal 4 presenter and adds a classic-queue fallback for Vulkan on devices without Metal 4.
- `tvport/backend.py` recognizes NVN, Vulkan and OpenGL shader-library layouts and sets the startup mode default from `--mode`.
- Keep extracted game files, keys, app bundles, captures and generated work folders out of commits. Do not commit a game's RomFS, NSP/XCI, prod.keys, or a compiled app.
